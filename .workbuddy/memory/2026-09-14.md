## 【BUG 修复】四册手册「出题」按钮点击无反应

**现象**：用户点击「出题 / 换题」没反应。

**根因（四册全部中招，同源复制）**：`pick()` 中
```js
else{let n;do{n=POOL[...]}while(...)}
cur=n;          // ← n 声明在 else 块内，块外访问 → ReferenceError
```
`let` 是块级作用域，`cur=n` 在块外 → 每次调用抛 `ReferenceError`。因为脚本末尾还有一句初始化 `pick()`，页面加载时就已静默报错。

**修法**：把 `let n;` 提到 if/else 之前；并加 `if(!POOL.length)` 空题库保护、`guard<50` 防死循环、换题判重用 `n===cur`（对象同一性，原写 `n.id===cur.id` 在 cur 为 null 时逻辑也脆）。

**验证方法（可复用）**：不必开浏览器。用 Node `vm` + 手写 Proxy/工厂函数假 DOM（getElementById 返回带 textContent/innerHTML/classList/querySelector 的桩对象，localStorage、window.scrollTo、confirm 都要桩）→ `vm.runInContext(code)` → 循环调 `ctx.pick()` 30 次 → 再桩填 `uans.value` 后 `ctx.judge()` 断言 100%。注意：`let/const` 声明的变量不会挂到 context 对象上，要读 `cur`/`POOL` 必须用 `vm.runInContext('cur.it.a.join("；")', ctx)`。
结果：四册 POOL 54 / 22 / 23 / 20，全对均判 100%，通过。

**教训**：同一份 JS 外壳复制到新手册时，凡是 `if{...}else{let x} use x` 这类块级作用域写法要一并检查；`node --check` 只能查语法，**查不出作用域错误**，必须实跑。
