- **过程管理 4 阶段**：流程规划（规·执·评·改）→ 流程执行 → 流程评价 → 持续改进。**"评价"必须在"改进"之前**。

  - 终点产出措辞不同：岗位法="流程清单 + 框架"，模型法="流程清单 + 总图"

- **执行保障 8 措施**：理·推·训·责（管人）+ 审·IT·制·文（管机制）；两条固化线 = IT 固化 + 制度固化
- **流程检查 4 方法**：稽·绩·满·审
- **流程稽查 7 步**：解·点·法·线·查·报·改，结构 4 准备 + 1 实施 + 2 收尾；第 1 步"理解流程目的目标及管理原则"必考
- **流程稽查 3 方法**：查·看·访
- **绩效 3 维**：效·率·弹｜**结果 4 分析**：标·内·同·稳（第 4 项判据：**控制图，稳定=受控，波动=非受控**）

## 【重大修复】第六册交付时是坏的（只有 P1）

**现象**：`流程管理_默写速记手册.html` 只有 27KB（同批其他册 40~104KB），HTML 里只有 `p1` 面板，
`mods` / `p2` / `numtable` / `p3` / `p4` / `p5` 全部丢失 → JS 一执行 `document.getElementById('mods')` 返回 null 直接抛错，
**卡片列表渲染不出来、页签也点不动**。

**漏网原因（重要）**：`verify.js` 的模拟 DOM 中 `getElementById` 对**任何** id 都返回 mock 元素，
所以残缺文件照样输出 `score:"100%"`——**verify 全绿 ≠ 文件完好**。

**根因**：`span(s, a, b, new)` 替换的是 `[a, b)` 区间——**`a` 被丢掉、`b` 保留**。
上一轮生成第六册时把起始标记漏写进 `new`，导致 `const MODULES = [` 与 P2~P5 整段丢失。

**修复**：以第五册（外壳完整）为模板，替换 title/h1/sub + P1 howto + P3 + P5 + MODULES + NUM + LS 后重建。
第六册 P3/P5 原内容已随文件丢失，按上一轮总结的要点重写了六组对比（含"稽绩满审"一符两用、3/4 各三次防串台总表）。

**教训已写入 skill**：
1. SKILL.md 新增「头号陷阱：span 替换 [a,b) 区间」专节，明确 `new` 必须自带起始标记、不得重复闭标记；
2. 新增「verify.js 有盲区：查不出面板整体丢失」专节 + **面板完整性检查脚本**（校验 24 个必需 id + 文件体积）；
3. 补充结构自检：`<div class="panel" id="` 恰好 5 次、`<script>` 恰好 1 次、以 `</html>` 结尾。
