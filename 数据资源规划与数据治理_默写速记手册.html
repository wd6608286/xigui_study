这一章为什么容易"背了但写错"

  1. 本章真正的坑是"串台"，不是"记不住"。全章有 5 套步骤（过程法 7 步 / 过程法 11 步 / 结构法 5 步 / 指标法 8 步 / 数据湖 5 步）和 4 张活动清单（数据治理 / 数据标准化 / 数据质量 / 数据安全）。每套单背都会，混在一起就张冠李戴。所以每条口诀都要绑定它的"方法名"一起背，不能只背口诀。
  2. 数字是本章最强的区分钩子。3 步是"主题数据库设计"，5 步有两个（稳定信息结构与数据湖治理），7 步是过程法核心、8 步是指标能力、11 步是过程法整体。记住"哪个方法几步"，一半的错位就自动排除了。
  3. 口诀只用于调取，不用于作答。看到题干先甩口诀，再逐字展开成标准表述。答题纸上写口诀不给分。
  4. 默写检验 > 反复阅读。本页答案默认折叠，必须先自己复述再展开对照。

① 三种规划方法：怎么选 + 优缺点

方法选它的场景优点缺点
基于稳定信息过程业务场景相对固定
前期数据积累较少		理论成熟、易理解、实现难度不大步骤繁杂、涉及因素多、数据稳定性较差
基于稳定信息结构业务场景经常变化
前期数据积累较多		理论较成熟、实施周期较短、数据稳定性好全局设计后置、初期工作量大、并行工作组织难度大
基于指标能力业务场景涉及决策
前期数据积累较少		直接支撑决策需求、设计思路清晰、数据稳定性好实现案例少、实施难度大、对设计人员要求高
选型口诀：固定业务 → 稳定过程 ｜ 业务常变且数据多 → 稳定结构 ｜ 决策 / 能力评价 → 指标能力
一句话区分两个"较少"：业务固定 + 数据少 → 过程；决策评价 + 数据少 → 指标能力。只有"数据积累较多"才选结构法。

② 稳定信息过程：核心 7 步 vs 整体 11 步（同一方法的两种说法）

阶段核心 7 步（精简版）整体 11 步（完整版）
前置— 无 —可行性分析 / 确定目标和范围 / 准备
定域与析业定义职能域 / 各职能域业务分析业务活动研究
析数与建模各职能域数据分析导出并建立数据模型
标准建立领域数据资源管理基础标准建立管理标准
三模型功能模型 / 数据模型 / 关联模型建立业务逻辑模型
数据组织— 无 —设计主题数据库 / 数据的分布分析
收尾— 无 —制定方案 / 审核评价方案
记忆钩子：11 步 = 7 步"前面加 3、后面加 4 之外的重组"——11 步比 7 步多的是前置三件（行、围、备）和后置四件（主、分、方、审）。
考试应对：题干问"核心步骤"或给了"职、业、数、标、能、统、联"这类口诀线索 → 写 7 步；题干问"整体/完整流程"或线索是"行、围、备" → 写 11 步。

③ 数据元 vs 元数据

对比项数据元元数据
一句话定义由一组属性规定其定义、标识、表示和允许值的数据单元，是数据的基本单元描述数据的数据，用来解释数据
关键特征有"允许值"（取值范围的约束）—— 这是它独有的本身不是数据内容，而是"关于数据的说明"
作用构成数据的基本单元，用于数据标准化描述、定位、寻找或发掘、评价、选择（5 项）
标准化位置数据标准化 4 项中的一项（数据元标准化）数据标准化 4 项中的一项（元数据标准化）
秒辨口诀：元数据 = "数据的说明书"，数据元 = "数据的最小积木"。
高频陷阱：数据元定义有"四个规定"——定义、标识、表示、允许值。只写"定义数据的数据元"会被扣条。

④ 两套"数据集"链条（别把顺序写反）

方法数据集处理链条顺序要点
基于稳定信息结构确定边界 → 获取初始数据集 → 建立核心数据集 → 完善目标数据集 → 建立信息模型先获取、再核心、最后目标；模型放在最后一步
基于指标能力决策评估收集 → 支撑指标分析 → 指标体系构建 → 建立指标数据模型并分析数据集 → 数据子集融合 → 核心数据集一致性检验 → 核心数据集评价 → 完善目标数据集先建体系再建模型；融合 → 检验 → 评价 → 完善，是"先合再验再评后善"
共同终点的都是"完善目标数据集"，但指标能力法多出一致性检验 + 评价两道验收关。
别写反："数据子集融合"在"一致性检验"之前——先合起来才能查一致性。

主题条数起手动作（区分钩子）活动清单

数据标准化4起手是 建立体系建立数据标准体系 / 元数据标准化 / 数据元标准化 / 数据分类与编码标准化
数据质量7起手是 定义（先定标准）定义高质量数据 / 定义数据质量战略 / 识别关键数据和业务规则 / 执行初始数据质量评估 / 识别改进方向并确定优先排序 / 定义数据质量改进目标 / 开发和部署数据质量操作
数据安全5起手是 识别需求识别数据安全需求 / 制定数据安全制度 / 定义数据安全细则 / 评估当前安全风险 / 实施控制和规程
四个主题的条数就是最好的锚：治理4 / 标准4 / 质量7 / 安全5。
口诀串起来：治理「规—定—实—入」、标准「一体两元一编码」、质量「高—战—关—评—优—定—开」、安全「识—制—细—评—控」。
顺序陷阱（安全）：数据安全是"先定制度、细则，再去评估当前风险"，最后实施控制 —— 不是"先评风险再定制度"。

这一章的 3 天打法（比上一章更快）

  1. Day 1（约1.5h）只背"方法—场景—步数"三角。先在白纸上写三个方法名，每个下面写：什么场景用它 + 它有几步 + 它的口诀。这一步不做细节，只做选型判断。目标：给一个场景（如"业务经常变化、数据积累较多"）能在 3 秒内说出方法名。
  2. Day 1（约1.5h）背 5 套步骤的展开。按"口诀首字 → 逐字展开"过 3 遍。当晚默写第 1 轮：5 套步骤 + 4 张活动清单。
  3. Day 2 只做错题 + 全量默写第 2 轮，重点攻「易混对比」页的 ④⑤ 两组（数据集顺序、四张清单串台）。
  4. Day 4 全量默写第 3 轮，附加"优缺点"专项：随机点一个方法，口述适用场景 + 优点 3 条 + 缺点 3 条。
  5. Day 7 / Day 15 各做一次全量默写，只要求"条数全对 + 关键词全中"，不要求逐字一致。

考场三个提分技巧（本章专用）

  1. 方法选用题先写"场景—方法"对照再补优缺点。这类题分值集中在"判断对不对"，先写出"业务相对固定、数据积累少 → 稳定信息过程"，再补三条优点三条缺点，结构分先拿到。
  2. 差值记忆法防串台。步骤题不要孤立背，改背"两套之间的差"：7 步比 11 步少「行围备 + 主分方审」；结构法 5 步比指标法 8 步少「体系构建 + 检验 + 评价」。记差比记全更省力。
  3. 四张活动清单用"起手动词"锚定。治理起手"规划组织"、标准起手"建立体系"、质量起手"定义"、安全起手"识别需求"。第一句对了，后面对应的整串动作就会自然带出来。
